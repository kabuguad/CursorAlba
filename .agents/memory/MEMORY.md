- [Portal service pattern](portal-service-pattern.md) — TypeScript interfaces from db.ts are type-only; use `import type { ... }` to avoid runtime "module does not provide export" errors in Vite.
- [DB storage key versioning](db-storage-key.md) — bump `STORAGE_KEY` constant in db.ts whenever the DB schema or seed data changes to force fresh seed in sessionStorage.
- [Portal data architecture](portal-data-architecture.md) — all portal data flows through `portalService.ts` → `useParentData` hooks with TanStack Query; parent hooks resolve child via `SelectedChildContext`.
- [Vite proxy offline detection](vite-proxy-offline.md) — when .NET backend is down, Vite proxy returns HTTP 502 (not raw ECONNREFUSED); `isOffline()` must check `response.status === 502 | 503 | 504` in addition to "Network Error" string.
- [Alber School API startup quirks](alber-api-startup.md) — .NET 10 API takes ~7s to start; use bash script with cd + dotnet run --no-build; skip waitForPort in workflow config or it always times out.
- [Admin API service layer](admin-api-service.md) — all real admin API calls go through `src/services/adminApiService.ts`; admissions hooks in useAdminData.ts must NOT use `.then(unwrap)` since the real service returns plain Promises; Teacher/Student namespace collisions in Presentation require type aliases.
- [.NET namespace collision fix](dotnet-namespace-alias.md) — Entities.Models.User namespace contains Teacher and Student classes; controllers in AlbaApi.Presentation must use type aliases (e.g. `using TeacherEntity = Entities.Models.User.Teacher`) when both the class and namespace are referenced.
